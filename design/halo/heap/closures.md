Decision: A heap closure records its callee explicitly, either a Lua prototype or a builtin ID, and a native closure (a `string.gmatch` iterator, a method of a `cjson.new()` instance) keeps its state in closed captures, because the two native closure kinds that shared the reserved no-prototype sentinel let call setup run a cjson instance method as a gmatch iterator (the [instance-method oracle script](../../../research/experiments/halo-oracle/scripts/libs/cjson-instance-methods.lua) failed with "attempt to index a nil value" where Redis 7.0.15 replies), and a variant that every reader matches exhaustively cannot alias the way two sentinel values can, as PUC Lua's closure tag separates C and Lua closures, instead of a reserved prototype sentinel per native kind or recognizing a native closure by the shape of its captures. Captures keep binding data with the closure through collection and handle reuse; reclaiming a cjson instance's configuration remains incomplete (docs/todo.md).

Rejected:
- One reserved no-prototype sentinel for every native closure, recognized by its captures: rejected because gmatch iterators and cjson methods both used it and call setup tested for an iterator first, so a cjson instance method ran as an iterator.
- A distinct reserved prototype value per native kind: rejected because the kinds stay distinguishable only while every new native closure picks an unused value and every reader compares against all of them, which no check enforces.
- Packing instance bits into the prototype word, or binding records in a VM registry: rejected because the prototype word cannot hold every builtin ID with the whole configuration index, and a registry's lifetime can diverge from recycled closure handles.
