Decision: The table hash part ports Redis 7.0.15's bundled `ltable.c` exactly: a chained scatter table with Brent's variation and `lastfree`, PUC's number and string hashes with Redis's changes, its array sizing and its border search, because `#` and `pairs` order depend on PUC's node placement and rehash timing, and the first open-addressing heap gave a different `#` from Redis's Lua on 68 of 2,336 traced tables with holes ([VM design, H1](../../../research/investigations/halo/VM.md#open-rulings)) while the port matches all of Redis's trace rows ([heap-core results](../../../research/experiments/halo-heap-core/RESULTS.md)), instead of an independent hash design; only tables and functions used as keys traverse in another order, since PUC hashes them by address.
