Decision: Provisionally, Halo counts array occupancy by power-of-two ranges and builds replacement arrays by copying the retained prefix once and initializing only the added suffix, because [six full-LTO pairs](../../../../research/experiments/halo-bench/RESULTS.md#six-pair-table-growth-result) improve the ten-million integer-table kernel by 25.70% with no regression beyond the fixed noise guard, while [ordinary, stress and unsorted comparisons](../../../../research/experiments/halo-bench/RESULTS.md#table-behavior-and-selection) retain replies, borders and observed iteration order, instead of classifying every array index as a numeric key and reinserting the entire array through general insertion. Retain Lua's size selection and suffix/hash reinsertion order and the existing replacement-on-success boundary; reopen when another host or workload changes the comparison or retained-prefix allocation/copying becomes a measured bottleneck.

Rejected:
- Growing a nonshrinking array in place with Whitefoot's `grow` once every failure point has passed: rejected because on the 14900K integer-table's median was unchanged (1.000 times main) although table growth takes about 30% of its samples, and Whitefoot's `grow` itself allocates, copies the filled slots and frees, so the change kept the work it targeted ([result](../../../../research/experiments/halo-bench/RESULTS.md#growing-the-array-in-place-result)); reconsidered when Whitefoot lowers `grow` through in-place reallocation.
