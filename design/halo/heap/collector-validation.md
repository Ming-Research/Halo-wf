Decision: Halo's embedding API is the only way a host or probe forces or observes the ordinary collector: opt-in safepoint collection stress (new engines default to off), a one-shot control that makes the allocation trigger due at the next safepoint, the saturating completed-collection count preserved across reset, and the heap's current logical bytes, because an embedding client needs a stated engine-lifecycle contract that survives changes to collector storage, instead of having each client set or interpret the collector's Heap fields itself. The one-shot control exists because stress bypasses the due check that a probe must exercise and a pause takes effect only after a collection, above the 64 KiB floor. Reopens when the production firn binding needs a control or observation this API lacks, or collector storage changes.


Decision: Halo gates collector calls at loop and call safepoints with direct reads of the existing stress, nonzero-limit and allocation-threshold conditions, retaining the ordinary collector's due check and root enumeration, because the [same-source pairs](../../../research/experiments/halo-bench/RESULTS.md#inline-safepoint-measurement) improve the unlimited loop by 10.28% with unchanged collector observations without coupling heap and budget state, instead of calling the full collector helper when no trigger holds or combining allocation and scheduling counters. This follows the owner's inline-predicate direction; reopen if trigger semantics change.

Decision: The embedding exposes last-collection statistics by object kind and a Lua-5.1-style collection pause setting that defaults to 200 percent, clamps below 100 percent, takes effect after the next collection and survives reset, because a host running one long-lived VM must see what a pause costs and tune its frequency without accessing heap fields, instead of fixed Lua defaults with no observation. This is provisional pending the owner's chosen measurement of collection work and a larger trigger multiplier on Firn's long-lived VM; the stop-the-world collector is unchanged.

Decision: Each collector edge that coroutines add is validated by a missing-edge control, a copy of the source that omits that one marking or closing line, which must change at least one recorded coroutine oracle reply under collector stress at budgets 1, 7 and 1000, by a differing reply, a native crash, or every case exiting natively with status 4, a runtime error in the host's setup chunk, before any reply while every case passes with the edge present, because Halo has no complete reachability verifier and a reply that differs from Redis 7.0.15's shows that a script depends on the edge, as the owner ruled for coroutine collector validation, instead of isolated embedding probes alone, which show that an edge retains its target but not that any script's reply depends on it; a timeout, a build failure or an unchanged comparison is never a detection. An edge whose control changes no reply gets an oracle script that makes a reply depend on it where one can be written, loses a duplicate holder that hides it, or is deleted when it marks nothing, and otherwise is validated by its isolated probe with the reason no script observes it recorded, as the owner ruled on the first run's nine unchanged edges ([results](../../../research/investigations/halo/COROUTINES.md#results)).

Rejected:
- Embedding clients set or read the collector's trigger and telemetry Heap fields directly: rejected because each client would depend on collector storage and interpret lifecycle details itself, which the owner also refused when approving the collection statistics without heap-field reads.
- The probe keeps writing the trigger fields as a recorded exception: rejected because the probe would still break on a storage change that no API contract covers.
