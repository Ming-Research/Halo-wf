Decision: The collector traces every execution, the running one included, through its thread cell: the main execution has a cell of its own, a collection parks the installed execution's buffers and checkpoints in its cell as a coroutine switch saves them and takes them back after marking, and the roots name the main and the current thread, so one marking routine covers running and suspended coroutines and a suspended one is traced only while reachable, because a root later added to the execution record is then marked in every state by the same lines, which the missing-edge controls exercise for running and suspended coroutines alike ([collector validation](../../../research/investigations/halo/COROUTINES.md#results)), instead of enumerating the installed execution's stack, frames, open upvalues and library records as separate roots beside a marker for suspended ones. Before parking, a checked test of the installed cell's live flag ends the script with an error instead of leaving the running execution unmarked; only a missing root, or a main cell whose allocation failed, frees that cell, and the three controls that stop every case before any reply stop at this test.

Rejected:
- Separate root enumeration of the installed execution, as Halo marked its one execution before coroutines, beside the thread marker for suspended ones: rejected because each field of the execution record would be marked in two routines, and a field missing from one would go unmarked only while its coroutine is in that state.
