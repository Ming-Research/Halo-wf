Decision: Lua-to-Lua calls, `__call`, `pcall`, `error` and host calls use the VM's own value stack and frame records, never the machine stack, while Lua code that the slow executor or a library function calls back (a `table.sort` comparator, `__tostring`, metamethods reached from the slow path) runs as a nested activation refused with "C stack overflow" at PUC's limit of 200, because script call depth then costs no machine stack and a script that reaches the callback limit gets Redis's error ([VM design, calls](../../research/investigations/halo/VM.md#3-calls)), instead of recursing on the machine stack for every Lua call. The machine stack that 200 nested activations use is unmeasured; this is provisional until it is (VM design, open ruling H2).

Decision: `table.sort` without a comparator, over elements `1..n` that all lie in the array part and are all numbers or all strings, sorts them in place synchronously by the steps of PUC's `auxsort` (same pivots, comparisons, swaps, bounds errors and smaller-half recursion, so the permutation is PUC's), while a comparator or any other case runs the resumable state machine whose comparisons can call back and be suspended, because the default comparison of such values calls no Lua and cannot suspend, and the state machine's frames and result slots made the sort kernel 2.8 times slower on the 14900K ([synchronous default sort](../../research/experiments/halo-bench/RESULTS.md#synchronous-default-sort)), instead of running every sort as the state machine.

Decision: `error(message, level)` counts levels as Lua 5.1's `lua_getstack` counts call records: each Lua frame is one level located at its current line, followed by one level without a location for each frame that a tail call into a Lua function replaced there (a tail call into a native function keeps the calling frame), which the frame record counts as Lua's `OP_TAILCALL` counts `ci->tailcalls` (a level landing there is a lost tail call), a `pcall` frame is one level without a location, and a library function that calls Lua back (a `table.sort` comparator or `__lt`, a `string.gsub` replacement function or `__index`, `table.foreach`, `__tostring` under `tostring`, the function `xpcall` runs) is one more level without a location, read when the error is raised from the library callback record that opened the nested activation, while a metamethod or generic-for iterator the VM calls adds no level, because Redis's Lua reports `error("m", 2)` in a sort comparator without a location and `error("m", 3)` at the `table.sort` call ([oracle](../../research/experiments/halo-oracle/scripts/lua-core/callback-error-levels.lua)), `lua_getstack` subtracts each Lua frame's `tailcalls` as it walks past it ([tail-call oracle](../../research/experiments/halo-oracle/scripts/lua-core/tail-call-error-levels.lua)), and the callback record already marks each such boundary, instead of a frame record pushed for every library callback, which adds work to each comparator call to serve only the error path, and instead of a one-bit tail flag, which counts two consecutive tail calls into one frame as one lost level.
