Decision: A host writes the text Redis 7.2.16 gives a double, as a double reply or as a number passed to `redis.call`, with `lib/fpconv`, a general package in this repository that ports `fpconv_dtoa` (Grisu2 with no exact fallback, its cached powers of ten and its layout), takes the spelling of NaN's sign as a parameter and names no host, while each host applies Redis's integer rule (`double2ll`) and `d2string`'s handling of NaN, the infinities and the zeros itself, because Redis writes these texts with that conversion, whose digits are not always the shortest that read back (1e23 is 99999999999999990000000, and 355 of the 16,922 nonzero values outside the integer rule that redis-server 7.2.16 wrote differ from the shortest; [oracle table](../../lib/fpconv/README.md#oracle-table)), and Halo's test host and Firn must write the same bytes, instead of the shortest form of Whitefoot's standard library or a copy of the conversion in each host.

Rejected:
- The shortest form of Whitefoot's standard library: rejected because the owner ruled that form exact, the shortest digits that read back, so it writes 1e+23 where Redis writes 99999999999999990000000 and differs from Redis on 355 of the 16,922 measured values.
- A copy of the conversion in each host: rejected because Halo's test host and Firn would keep two ports of one algorithm byte-identical, each with its own check against the same table.
- Redis's integer rule and `d2string`'s special values inside the package: rejected because they are Redis's reply rules rather than fpconv's, and a package that names no host stays usable as the codec packages are.
