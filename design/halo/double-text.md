Decision: A host writes the text Redis 7.2.16 gives a double, as a double reply or as a number passed to `redis.call`, with `lib/fpconv`, a general package in this repository that is a pure port of `fpconv_dtoa` (Grisu2 with no exact fallback, its cached powers of ten, its layout and its special values, a NaN's sign included) and names no host, while each host applies Redis's rules around it: for a double reply `d2string`'s, which writes every NaN as nan, the infinities and the zeros itself, then an integral value within Redis's integer rule (`double2ll`) as an integer, then the conversion; for a `redis.call` argument `luaArgsToRedisArgv`'s, the integer rule and then the conversion with no other rule, because Redis writes these texts with that conversion, whose digits are not always the shortest that read back (1e23 is 99999999999999990000000, and 355 of the 16,922 nonzero values outside the integer rule that redis-server 7.2.16 wrote differ from the shortest; [oracle table](../../lib/fpconv/README.md#oracle-table)), and Halo's test host and Firn must write the same bytes, instead of the shortest form of Whitefoot's standard library or a copy of the conversion in each host.

Rejected:
- The shortest form of Whitefoot's standard library: rejected because the owner ruled that it follows the exact definition, the fewest digits that read back, then the nearest, then the even, and that Redis's text is reproduced downstream (option A of the status board's decision card on the standard library's shortest output, ruled 2026-10-12, as [card 1 of Whitefoot's float-text design](https://github.com/Ming-Research/Whitefoot/blob/ed7f0e5ac2d9b0bbd037a06070d5876ca7ed3604/research/investigations/float-text/DESIGN.md#card-1-does-the-standard-librarys-shortest-output-follow-the-exact-definition-with-rediss-grisu2-output-reproduced-in-the-downstream-projects) proposed it), so it writes 1e+23 where Redis writes 99999999999999990000000 and differs from Redis on 355 of the 16,922 measured values.
- A copy of the conversion in each host: rejected because Halo's test host and Firn would keep two ports of one algorithm byte-identical, each with its own check against the same table.
- Redis's integer rule and `d2string`'s special values inside the package: rejected because they are Redis's reply rules rather than fpconv's, and a package that names no host stays usable as the codec packages are.
- A package parameter that chooses whether a NaN's sign is written: rejected because it carries a reply rule, `d2string`'s unsigned nan, into the general package, which then no longer writes what `fpconv_dtoa` writes.
