Decision: Provisionally, the interpreter is the guaranteed self-tail call `run`, whose `pc`, `base` and `kbase` parameters carry the facts every arm needs (`pc` inside the code, 256 stack slots above `base`, 256 constants above `kbase`), which each arm re-establishes before the next dispatch, the selected hot arms by proving only what they change and the others through a shared epilogue that checks the windows ([continuations](dispatch/continuations.md)), only until Whitefoot accepts the same interpreter as a plain `loop { match }`, because an interpreter is to be written as `loop { match }` with the compiler emitting its tail calls, while today the checker refuses that loop where arms that update different loop variables join and lose the window facts ([VM design, section 0](../../research/investigations/halo/VM.md#0-the-finding-that-shapes-the-dispatch-loop)), a gap Whitefoot is to close, instead of the self-tail form as a design choice of its own.

Decision: Stack slots are authoritative: no Lua value lives only in a machine register across a dispatch, because the collector then finds every root in the stack, the frames and the other root sets ([VM design, values](../../research/investigations/halo/VM.md#1-values)), instead of caching values in registers, which a later accumulator would write back before every safepoint.

Decision: Execution is budgeted: a counter in the VM decreases only at `ForLoop`, `TForLoop`, a backward jump, `Call` and `TailCall`, and at zero the run saves its position and returns `Budget`, because the host must stop a script between slices and restart it, and loops and calls bound every path between those points, instead of testing a counter or clock at every instruction ([VM design, dispatch](../../research/investigations/halo/VM.md#5-dispatch)).

Decision: Each instruction handler implements only the common case and leaves everything else to one shared slow executor, which performs coercion, metamethods, hash misses, `__index` chains and read-only refusal and writes the destination slot itself, because in Lua the slow path usually succeeds and one executor keeps rare cases out of every handler ([interpreter inputs](../../research/investigations/halo/DESIGN.md#interpreter-inputs)), instead of complete semantics in each handler.

Decision: Concatenation's common case is every run of adjacent string or number operands: its handler joins each run into one buffer, converting numbers in place with Lua's number format as `luaV_concat` does, and interns the result once, leaving `__concat` and errors to the slow executor, because joining one pair at a time through the slow executor allocated and interned every intermediate string and made the concat kernel 27% slower on the 14900K ([batched concatenation](../../research/experiments/halo-bench/RESULTS.md#batched-concatenation)), instead of sending every pair, and its number conversion, to the slow executor.

Decision: A table store's common case includes a missing key in a live table with no metatable that is not read-only: the fast store inserts it through the table's own insertion path, with its errors, leaving tables with a metatable, read-only tables and invalid tables to the slow executor, because sending every new key to the slow executor repeated its lookup and validation and made the integer-table kernel 1.16 times slower on the 14900K ([table stores](../../research/experiments/halo-bench/RESULTS.md#table-stores-without-the-slow-executor)), instead of treating every missing key as a hash miss for the slow executor.

Rejected:
- A `loop { match }` that re-checks the windows at run time before every dispatch: rejected because it hides the checker gap behind run-time comparisons instead of closing it.
