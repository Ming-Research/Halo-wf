Decision: Each execution state, main and every coroutine, keeps an exclusive upper bound on its open-upvalue stack positions, saved and restored with that state's checkpoints on a switch, so a Lua return or a Lua tail call replacing its frame skips closing with one comparison when the frame base is at or above the bound, because the handle list otherwise requires dependent loads through the checked upvalue cell even when nothing needs closing, and this change together with reading only the returning frame's needed fields passed the fib-at-least-3%-faster keep rule on the 14900K ([measurement](../../../research/experiments/halo-bench/RESULTS.md#a-cheaper-lua-return)), instead of inspecting the open-upvalue list on every return. The bound may be too high, costing a scan, but never too low, which would leave an upvalue open when its slot is reused; it is zero for an empty list and greater than every open slot otherwise. Capture only raises it; closing lowers it only from the highest remaining live, owned open cell or to zero when the list empties. Upvalue cells remain the authority and every access stays checked.

Rejected:
- Inspecting the open-upvalue list on every return: rejected because a nonempty list can contain only captures below the returning frame, yet reaching their positions still incurs the checked cell loads that the bound avoids.
- A parallel buffer of open stack positions: rejected because it duplicates the list's ordering and length invariant, which Whitefoot does not preserve across a buffer swap, while a scalar bound needs no paired indexes ([comparison](../../../research/investigations/halo/VM.md#open-upvalues-a-cheaper-nothing-to-close-test)).
- Replacing handles with stack-position-and-handle entries for this return test: rejected because an exact cached position is stronger than the one-sided bound the test needs and enlarges each entry and coroutine buffer charge; its faster list removal remains a separate option for a capture-heavy workload ([comparison](../../../research/investigations/halo/VM.md#open-upvalues-a-cheaper-nothing-to-close-test)).
