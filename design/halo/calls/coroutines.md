Decision: A coroutine owns its execution record, the value stack, frame records, open-upvalue list, library continuation records and the run's checkpoints, in a thread cell, a heap slab kind of its own, and `resume`, `yield` and a coroutine's return or error exchange that record's buffers with the interpreter's and continue the other coroutine in the same dispatch loop, because a switch then takes no native level and no machine stack, as [calls](../calls.md) chose for Lua calls, and what this adds to scripts without coroutines, an owner check on every open-upvalue read and write among it, left none of the eight halo-bench kernels slower than main on the 14900K beyond its larger range plus the twin's difference, the kernel that writes and reads open upvalues in a loop included ([comparison 2](../../../research/investigations/halo/COROUTINES.md#results)), instead of running each resume as a nested activation of the interpreter. An open upvalue names its owning coroutine with its slot, so a closure called from another coroutine reaches the owner's saved stack; a switch requested inside a library callback waits until the callback's native levels have parked in the continuation records a budget suspension uses; and nested resumes count toward PUC's limit of 200 native levels, a yield being refused across a metamethod, library callback, `pcall` or `xpcall` entered since the coroutine's resume, as PUC 5.1 refuses it.

Rejected:
- Resume as a nested activation that re-enters the interpreter, as PUC's `lua_resume` re-enters `luaV_execute`, with yield parking the coroutine through the budget suspension's records: rejected because every resume would take one of the 200 native levels and machine stack whose size is unmeasured, and every yield would copy the whole value stack as a suspension inside a callback does; it was kept only as the fallback had the swapped records failed comparison 2, which they passed.
- An open upvalue that names only a stack slot, read in whichever stack is running: rejected because with one stack per coroutine a closure created in one coroutine and called from another would read and write the wrong stack.
