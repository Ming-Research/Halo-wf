Decision: A host extends Halo through one `Host<E>` interface whose call receives the host's environment, the VM and the stack window of its arguments, and returns results, raises, stops the run with the stack intact, or leaves the call pending, because a host's functions need its own state and a host must be able to stop a script at a clean point and restart it, instead of registering closures over host state inside the engine ([VM design, embedding](../../research/investigations/halo/VM.md#6-embedding)).

Decision: A run that exhausts its budget is suspended and resumes where it stopped, inside nested library callbacks too through explicit continuation records, while a run that a host function stops stays ended until the host resets or starts a script, because the host's slice protocol either continues a budgeted run or abandons it and restarts the script, and treats a stop from its own function, such as an undeclared key, as the end of that attempt, instead of a budget that ends the run or a stop the host could resume.

Decision: A host function may leave its call pending: the run suspends at the call, inside nested library callbacks too through the same continuation records as a budget suspension, the host reads the call's arguments, and it then completes the call with results or fails it with an error value, after which the run continues as if the call had returned or raised, so an enclosing `pcall` catches the error, because a host can need state its function cannot reach to answer a call, as Firn runs each script inside an `atomic` statement whose keyspace references a script's commands need and its environment cannot store a reference, instead of passing such references through `start`, `resume` and the dispatch loop to every host call.

Rejected:
- Running a script's commands outside the host's `atomic` statement, with only owned data in the environment: rejected because the script's commands would no longer run atomically, as Redis scripts require.
- Passing the host's references as parameters through `start`, `resume` and `run` to each host call: rejected because `run` already takes eight parameters, the arm64 argument-register count, and [E0](https://github.com/Ming-Research/Whitefoot/blob/ff1894f7b53c6449b02c1e6a57986e25aebdb443/research/experiments/match-dispatch/RESULTS.md#verdicts-under-the-recorded-criteria) measured a dispatch with a ninth parameter 8% slower and with a tenth 43% slower.
